# 时空方位 · 算法原理

> **从用户输入到方位显示的完整计算链路**

本文详细描述用户从选择日期 + 时辰，到页面显示 8 方位八门九星图表的整个算法过程。

---

## 📊 **总览：6 步计算链**

```
[1] 用户输入: 公历日期 + 时辰
    ↓
[2] 干支计算: dayGanZhi (日柱) + dayYinYang (阳/阴)
    ↓
[3] 数据查找: map[dayGanZhi][dayYinYang='阳' ? '阳遁' : '阴遁']
    ↓
[4] 字段提取: 中宫星 + 喜神方 + 大吉方 + 8方位×(门+星)
    ↓
[5] 几何布局: 按先天八卦方位排成 3×3 洛书九宫格
    ↓
[6] 颜色语义化: 喜神方金黄/大吉方绿/中宫特殊
```

## 🎯 **步骤 2：干支计算**

### 2.1 基准日

**基准日**：`1940-09-18` = 甲子日

**位置**：`src/lib/data.ts:11`

```typescript
export const BASE_DATE = new Date(Date.UTC(1940, 8, 18)) // 1940-09-18
```

### 2.2 计算日干支

**算法**：
1. 计算用户日期距基准日的天数差 `delta`
2. **日天干**：`TIAN_GAN[((delta % 10) + 10) % 10]`
3. **日地支**：`DI_ZHI[((delta % 12) + 12) % 12]`
4. **日柱**：`dayGan + dayZhi` （如 "乙卯"）

**位置**：`src/lib/data.ts:55-66`

```typescript
export function getDayGan(year, month, day): TianGan {
  const d = new Date(Date.UTC(year, month - 1, day))
  const delta = Math.round((d.getTime() - BASE_DATE.getTime()) / 86400000)
  return TIAN_GAN[((delta % 10) + 10) % 10]
}

export function getDayZhi(year, month, day): DiZhi {
  const d = new Date(Date.UTC(year, month - 1, day))
  const delta = Math.round((d.getTime() - BASE_DATE.getTime()) / 86400000)
  return DI_ZHI[((delta % 12) + 12) % 12]
}
```

### 2.3 判断阳遁/阴遁

**算法**：基于**日干的阴阳属性**
- **十天干**（按顺序）：`甲乙丙丁戊己庚辛壬癸`
- **奇数索引**（0/2/4/6/8 = 甲/丙/戊/庚/壬）= **阳干** → 阳遁
- **偶数索引**（1/3/5/7/9 = 乙/丁/己/辛/癸）= **阴干** → 阴遁

**位置**：`src/lib/engine.ts:197`

```typescript
const dayYinYang: '阳' | '阴' = TIAN_GAN.indexOf(dayGan) % 2 === 0 ? '阳' : '阴'
```

**示例**（以 `2026-08-09 乙卯日` 为例）：
- 日干 `乙` → 在 TIAN_GAN 中索引 = 1 → 1 % 2 = 1 ≠ 0 → **阴日**
- → 使用 **阴遁** 数据

## 🎯 **步骤 5：几何布局**

### 5.1 先天八卦方位排布

九宫格按**先天八卦**方位（顺时针 180°）排布：

```
┌─────────┬─────────┬─────────┐
│  东南    │   南    │   西南   │   ← 第一行（南向）
├─────────┼─────────┼─────────┤
│   东    │  中 宫  │   西    │   ← 第二行（中央）
├─────────┼─────────┼─────────┤
│  东北    │   北    │   西北   │   ← 第三行（北向）
└─────────┴─────────┴─────────┘
```

**索引映射**（八方数组 → 九宫位置）：
| 九宫位置 | 数组索引 | 方位 |
|---|---|---|
| [0,0] 左上 | 八方[3] | 东南 |
| [0,1] 上中 | 八方[4] | 南 |
| [0,2] 右上 | 八方[5] | 西南 |
| [1,0] 左中 | 八方[2] | 东 |
| [1,1] 中央 | - | 中宫 |
| [1,2] 右中 | 八方[6] | 西 |
| [2,0] 左下 | 八方[1] | 东北 |
| [2,1] 下中 | 八方[0] | 北 |
| [2,2] 右下 | 八方[7] | 西北 |

## 🎨 **关键设计决策**

### 1. **数据预生成 vs 实时计算**
- **选择**：预生成 JSON 文件（110KB）
- **原因**：Excel 数据是手算结果（10 处校勘后），无法用简单公式还原
- **优点**：查询 O(1)，切换日期/时辰即时响应

### 2. **异步加载**
- 首页只 fetch `acupoints-index.min.json` (~4KB)
- 时空方位 JSON (~110KB) 按需异步加载
- 用户切换日期/时辰时**不重新 fetch**，只换 key

### 3. **数据 schema 简化**
- 原始 Excel: 24 列（含校勘状态、原书值、标准值等）
- JSON: 只保留**标准值**（校勘后）
- 字段重命名：方位名 → 单字（中文化）

### 4. **几何布局选择**
- **先天八卦方位**（用户指定）：东南→南→西南 → 东→中→西 → 东北→北→西北
- 区别于**后天洛书九宫**（东南→南→西 → 东→中→西 → 东南→北→西北）

### 5. **8 方位索引固定**
- 八方数组索引: `[北, 东北, 东, 东南, 南, 西南, 西, 西北]`
- 与 Excel 数据顺序一致，便于直接索引
